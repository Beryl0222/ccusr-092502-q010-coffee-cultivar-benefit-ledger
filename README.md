# 咖啡良种权益分配账

云南咖啡良种推广中，育种单位、苗圃、农户、合作社与加工厂对同一批种苗和后续鲜果
各有承诺。本服务用**仅追加事件流 + 可逆批次谱系**把"一笔品牌溢价如何穿过批次谱系
到达农户"做成可证明的账目：品种版本、繁育批次、授权范围、种苗交接、地块实种、
绿色农事、鲜果交付（收购回执）、检验等级、销售仓口、溢价冻结与结算规则全部留痕，
拆分/混批/加工保持数量守恒。

## 核心原则

- **事实不删改**：业务事实一旦接收即不可原地修改；品种纠错、检验复核、合作社
  资格变更都以**新版本事件 + 差额结算**表达，已交付与已付款事实始终保留。
- **可逆谱系**：销售批次可逐级向上还原到收购回执与地块，地块可向下定位到全部
  销售批次；销售千克按质量比例摊回每张收购回执，加工损耗按比例分摊。
- **数量守恒**：拆分、混批进出严格相等；加工允许出成率损耗但产出不得大于投入；
  任何支取不得超过批次余量；批次冻结累计不得超过批次诞生量。
- **职务互斥**：良种授权人（LICENSOR）、检验员（INSPECTOR）、结算人（SETTLER）
  三类职务由不同主体担任，事件只能由对应职务主体签署，不能互相代签。
- **冻结上限**：分配合计（含复核后的新版本与人工调整）不得超过冻结的销售溢价；
  人工调整必须填写理由。
- **回执不重复结算**：收购回执号全局唯一；同一回执已结算千克累计不得超过其
  交付千克，结算请求以 event_id 幂等重放。
- **争议冻结付款**：结算单存在未裁决争议期间暂停付款。
- **农户数据隔离**：农户接口只能看到自己的交付、农事依据与分给自己的结算行。
- **可中断恢复**：状态完全由 JSONL 事件重放得到，重启后继续处理待结算仓口、
  待重算差额、待裁决争议、待付款结算单与待追回超付。

## 目录

- `contracts/domain.json`：聚合、事件、三类签名职务与七条账目不变量。
- `src/domain.py`：角色/职务/计量单位常量与定点金额、数量运算。
- `src/envelope.py`：共用事件信封校验（时间必须带时区、版本为正整数）。
- `src/lineage.py`：批次谱系图、数量守恒、收购回执摊配、品种版本解析与纠错。
- `src/store.py`：仅追加 JSONL 事件存储，event_id 去重、版本连续、重放恢复。
- `src/ledger.py`：事件重放投影与读模型（主体、地块、检验、仓口、结算、争议）。
- `src/commands.py`：命令层，所有业务不变量校验与结算计算引擎、农户视图、
  品牌溢价穿透证明、待办清单。
- `data/sample.json`：单事件信封联调样例。
- `data/sample_flow.json`：33 个事件的端到端中文样例（含事件流、农户视图、
  穿透证明与中断恢复时的待办）。
- `scripts/smoke_flow.py`：可运行的端到端演示脚本。
- `scripts/export_sample.py`：重新生成 `data/sample_flow.json`。
- `tests/`：谱系守恒、事件存储、业务不变量共 38 个测试。

## 一笔溢价的穿透路径

```
品种版本/授权 → 繁育批次 → 种苗交接 → 地块实种 → 绿色农事
      → 鲜果交付(收购回执) → 混批 → 加工(出成率) → 拆分 → 检验分级
      → 销售仓口冻结(数量×单价) → 结算规则分配 → 付款
                                   ↑ 复核/纠错/资格变更只追加差额版本
```

结算金额按 `千克 × 每千克溢价 × 等级系数 × 绿色履约系数 × 角色比例` 计算，
未达等级或绿色技术未履约的部分进入联盟代管（RESERVE），不进任何受益人，
因此分配合计恒等于冻结的品牌溢价。

## 测试与构建

```bash
python3 -m unittest discover -s tests
python3 -m compileall -q src tests
PYTHONPATH=. python3 scripts/smoke_flow.py
```

全部仅使用 Python 标准库（Python ≥ 3.11）。金额与数量使用 `Decimal` 定点运算，
禁止以 float 入账。
