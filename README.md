# 咖啡良种权益分配账

本项目保存 咖啡良种权益分配账 服务的领域名词、事件信封、事件溯源内核与联调样例，
支撑云南咖啡产区良种推广中“品牌溢价可穿过批次谱系、公平回到真正履约农户”的后端能力。

## 目录

- `contracts/domain.json` —— 聚合、事件、角色、计量单位与十条领域不变量合同。
- `src/envelope.py` —— 共用事件信封校验（字段、时区、版本）。
- `src/store.py` —— append-only 事件存储：JSONL 落盘、聚合版本无间隙、event_id/幂等键唯一、订阅重放。
- `src/ledger.py` —— 领域内核：谱系投影、合格性重算、分权、结算/差额/人工调整、农户视图与溢价溯源。
- `tests/` —— 信封合同测试与全量不变量测试。
- `scripts/demo.py` —— 端到端联调演示（含绿色断链、争议裁决、复核升等、中断恢复）。
- `data/sample.json` —— 基础信封联调样例。

## 可逆谱系

```
品种版本 → 授权（范围/期限/株数）→ 繁育批次 → 种苗交接
        → 地块实种 → 农事记录/绿色核验 → 鲜果采收（收购回执）
        → 拆分/混批（逐地块成分守恒）→ 入仓交付
        → 检验定级/复核 → 销售仓口溢价冻结 → 提案(内嵌依据) → 过账 → 付款
```

纠错不回写：品种纠错、检验复核、合作社资格变更都只追加新版本事件，
结算时按“当前最新版本”重算并与已入账事实求差额（`SETTLEMENT_ADJUSTMENT_POSTED`），
已交付与已付款事实永不删除或原地改写。

## 关键不变量（详见 contracts/domain.json）

1. **数量守恒**：拆分按地块成分比例（最大余数法分尽整数克）、混批为投入之和、入仓量等于批次量；
   累计繁育不超授权株数、出苗不超批次产量、实种不超持有种苗。
2. **收购回执幂等**：同一 `receipt_id` 重送返回首次采收事件，不重复进入结算。
3. **冻结池上限**：累计净分配（农户+合作社+品种权分成，含差额与人工调整）永不超过冻结溢价。
4. **分权互斥**：良种授权人、检验员、结算人按事件类型分权；同一自然人行使过其中一类职权后，
   不得再代签另外两类，互斥台账本身也是事件投影，重启后仍然生效。
5. **人工调整**：必须填写理由，净额不得突破冻结池，且不得把农户冲减到已付款额以下。
6. **合格性**：品种版本在授权范围/期限内、绿色核验通过、合作社资格有效、无未决争议；
   等级一律取最新检验版本的权重。
7. **争议挂起**：未决争议成分不进提案；裁决后按新版本补发（正差额）或冲减未付余额（负差额）；
   已付款部分若需追回，系统拒绝直接冲账，提示先走追款/争议。
8. **依据内嵌**：提案逐交付内嵌谱系边、检验版本、绿色核验事件、品种/授权与资格状态、加权克数。
9. **农户隔离**：农户接口只返回本人地块、本人交付成分与本人结算依据。
10. **中断恢复**：进程重启后从 JSONL 重放，待结算交付、未决争议、已过账待付款全部重建，
    已过账提案不会重复过账。

## 运行

```bash
# 单元测试（35 项，仅标准库）
python3 -m unittest discover -s tests

# 编译检查
python3 -m compileall -q src tests scripts

# 端到端联调演示
python3 -m scripts.demo
```

## 领域边界

事件标识、聚合标识、发生时间与版本用于模块间确定交接。业务事实一旦被接收就不应原地改写，
更正由后续事件表达。持久化采用 append-only JSONL（写入即 flush+fsync），
正式服务可替换为支持同等顺序与唯一约束的事件库；权限接入、对外 HTTP 接口与并发事务
由正式服务在本内核之外实现。
